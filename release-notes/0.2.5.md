# steward v0.2.5

## Features

- **Answers say how fresh they are.** `steward ls` and `steward tree` start
  with a line on stderr naming the scan they are as of, when the next one
  is due, and the `steward scan` that updates them now. `stat` (in the CLI
  and the API) gains `scanned` with the same facts, and `offline` when the
  path's volume is not mounted, so an unmounted folder is no longer shown as
  if it were live.
- **Errors name the next command.** A path that exists on disk but isn't in
  the index yet says so and names the folder to scan; a path outside every
  root names `steward put-root`.
- `steward ls` and `steward tree` have a header row and `--json`. `tree
  --json` nests `children` and counts the rest of each folder in `more`.
- `steward scan FILE` works: it reads the file's folder again.

## Bug fixes

- `steward … 2>&1 | head` no longer panics (exit 101) when `head` closes the
  pipe before steward's closing note.
- `steward dups` walks only the folder asked about, so it answers in
  seconds rather than minutes. Hard links share their space, so they are
  listed but no longer counted as wasted.
- `steward ls FILE` prints the file's line instead of nothing.
- `steward resolve` and `steward inspect` without arguments are an error,
  not an empty answer.
- JSON from the CLI keeps its fields in order (`path` first) however it
  was built.

## Breaking changes

- `steward ls` and `steward tree` print a header row on stdout first.
  Scripts should use `--json`.
- `duplicates` leaves out content whose paths are all hard links to one
  inode, and its `wasted` counts extra inodes, not extra paths.

## Upgrade notes

- `steward upgrade` (or `curl -fsSL https://toppk.github.io/steward/install.sh | sh`)
  installs it and restarts the service. Scan times are recorded from the
  first scan after the upgrade, which runs at startup.
